3 🧰 Google Google Blog · 11/19 #Gemini API#MCP#에이전트 개발

Gemini API, 도구 수백 개 쓰는 'Tool Retrieval' 공개

Introducing Tool Retrieval in the Gemini API

구글이 Gemini Interactions API에 Tool Retrieval을 프리뷰로 공개함. 에이전트는 도구의 이름·설명만 보다가 필요할 때 파라미터 스키마를 불러와(지연 로딩), 도구가 많아도 입력 토큰을 줄일 수 있음.

  • tool_search 추가 후 도구에 defer_loading:true 설정
  • Gemini 3.6 이상·Gemini 4 전 모델 지원, 별도 요금 없음
  • mcp_server에 설정하면 해당 서버 도구 전체가 지연 로딩

💡 왜 중요? 도구가 많아질수록 프롬프트가 길어져 비용·정확도가 나빠지는 문제를 API 차원에서 해결하려는 시도임. 앤트로픽·OpenAI의 툴 검색 기능과 비슷한 방향임.

💬 오늘의 코멘트

오늘 AI 소식은 OpenAI dots, Gemini Tool Retrieval처럼 에이전트가 더 많은 도구를 쓰고 더 오래 혼자 일하게 만드는 쪽으로 모임. 그런데 재무 현장 사례인 KPMG KCi, 스코샤뱅크, Zapier는 모두 '초안은 AI, 최종 판단·승인은 사람'이라는 같은 구조를 택함. 결국 재무 AI의 경쟁력은 모델 성능보다 어디서 사람이 승인하고 어떻게 추적할지 정하는 통제 설계(internal controls)에 있음. 회계 실무로 통제를 익힌 사람이 에이전트를 직접 만들 줄 알면 감사·여신·슈퍼펀드 어디서든 흔치 않은 인재가 됨.

📖 오늘의 용어

전수 분석 (Full-population testing) — 일부 표본 대신 거래 100%를 검사하는 감사 방식임. 예전엔 데이터·시간 한계로 표본감사(sampling)를 했지만, 이제 AI·자동화로 모든 거래에서 이상치를 찾고 감사인은 걸러진 항목 검토에 집중함.
